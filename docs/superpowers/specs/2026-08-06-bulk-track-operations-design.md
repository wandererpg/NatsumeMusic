# 曲目批量操作设计规格

## 目标

用户打开一个已经创建的游戏音乐文件夹后，可以选择当前列表中的多首曲目，并批量执行收藏、取消收藏、移动到另一个游戏音乐文件夹、加入播放列表和删除操作。批量操作必须适用于虚拟滚动列表，并避免文件与数据库状态不一致。

## 范围

- 批量选择只在“全部音乐”下打开某个具体游戏文件夹时启用。
- “全选”只选择当前搜索文字和“全部 / 音乐 / 语音”筛选后的曲目。
- 支持逐项勾选、表头全选、Shift 连续选择和清空选择。
- 支持批量收藏、批量取消收藏、移动到另一个游戏音乐文件夹、加入一个现有播放列表和批量删除。
- 不在“最近添加”“收藏”“播放列表”或跨游戏的“全部音乐”集合中启用批量操作。
- 本期不支持复制曲目、不支持创建批量操作历史，也不支持撤销已经完成的操作。

## 界面与交互

### 选择模式

曲目表新增第一列复选框，原曲目编号顺延。点击单曲复选框切换选择；按住 Shift 再点击复选框，选择或取消上次锚点与当前曲目之间的连续范围。表头复选框作用于当前筛选结果：未全选时全选，已全选时取消当前结果的选择，部分选择时显示半选状态。

选择状态以曲目 ID 保存，不依赖当前挂载的虚拟列表行，因此滚动出视口不会丢失选择。游戏、分类、搜索条件或当前文件夹发生变化时清空选择，避免对不可见的旧集合误操作。

### 批量工具栏

至少选择一首曲目后，曲目标题下方、列表上方出现批量工具栏，包含：

- `已选择 N 首`
- `收藏`
- `取消收藏`
- `移动到…`
- `加入播放列表…`
- `删除…`
- `取消选择`

操作执行期间禁用工具栏和选择控件，并显示处理中状态，防止重复提交。

### 目标选择

“移动到…”打开游戏文件夹选择窗口，列出除当前游戏外的现有游戏。确认后，曲目被移动到目标游戏对应的 `音乐` 或 `语音` 子目录，保留各自分类、曲名、收藏状态和播放列表关系。目标目录存在同名文件时沿用现有的安全重命名策略，不覆盖原文件。

“加入播放列表…”复用播放列表选择样式，但标题显示选中数量。一次只能选择一个目标播放列表；已经存在的曲目关系自动忽略，不视为错误。

### 删除确认

“删除…”打开确认窗口，明确显示曲目数量，并提供两个独立操作：

1. `仅从音乐库移除`：删除数据库曲目记录和关联的播放列表关系，保留硬盘文件。
2. `同时删除硬盘文件`：删除数据库记录、播放列表关系及音乐库目录中的对应文件。

两个操作都需要二次确认。删除硬盘文件只允许作用于当前配置的音乐库根目录内部；路径越界时拒绝删除并报告错误。

## 架构

### 共享协议

新增批量请求与结果类型。请求包含非空、去重后的曲目 ID 列表，以及对应操作参数。结果返回成功曲目 ID 和逐曲目失败信息，使界面能够刷新成功项并保留失败项的选择。

批量操作使用专用 IPC 请求，不由渲染进程循环调用单曲接口。IPC 层限制最大曲目数量、验证 ID、目标游戏或播放列表 ID，并拒绝请求中未声明的字段。

### 主进程服务

新增独立的批量曲目服务，负责：

- 批量设置 `is_favorite`，收藏与取消收藏使用明确目标值，不反转每首曲目的原状态。
- 在一个数据库事务中将多个曲目加入播放列表，重复关系忽略。
- 移动曲目前读取并锁定源曲目与目标游戏；按分类创建目标目录，分配不冲突文件名，先移动文件，再在数据库事务中更新 `game_id`、`file_path` 和 `file_name`。数据库失败时将已经移动的文件回滚到源路径。
- 删除时根据模式决定是否处理硬盘。仅移除模式只修改数据库；删除硬盘模式先把文件移动到音乐库内的临时暂存目录，数据库事务成功后再清理暂存文件，事务失败则恢复原文件。

每项失败都记录曲目 ID、面向用户的原因和内部错误信息；同一请求中的其他安全独立项可以继续处理。数据库批量写入使用事务，文件移动保持逐项可回滚。

### 数据库

曲目查询层新增：

- 按 ID 列表读取曲目并验证其全部属于当前源游戏。
- 批量设置收藏状态。
- 批量更新曲目的游戏归属和存储路径。
- 批量删除曲目记录。

移动操作不创建新曲目 ID，因此收藏状态、播放列表关系、创建时间和自定义曲名保持不变。游戏与播放列表计数继续从数据库查询结果生成，不维护额外计数字段。

### 渲染层

`TrackTable` 接收受控选择属性和回调，复选框与虚拟滚动兼容。`App` 管理当前选择集合、操作弹窗、执行状态和结果提示。资料库 store 暴露单次批量 API，并在操作完成后重新加载当前查询、游戏列表和播放列表，避免手工维护多个集合产生偏差。

## 数据流

1. 用户在具体游戏曲目列表中选择曲目。
2. `App` 根据当前筛选结果维护所选曲目 ID。
3. 用户选择批量操作并确认参数。
4. 渲染进程向专用 IPC 发送一次批量请求。
5. 主进程验证请求和曲目归属，调用批量服务。
6. 服务执行数据库事务及必要的文件移动或暂存，返回逐项结果。
7. store 重新加载当前曲目、游戏和播放列表。
8. 成功曲目取消选择；失败曲目保持选中并显示错误摘要。

## 错误处理与安全

- 空选择、重复 ID、超出上限、目标等于源游戏、目标不存在和路径越界在执行前拒绝。
- 默认单次最多处理 2,000 首，避免异常请求占用过多内存或阻塞主进程。
- 文件移动不得覆盖目标现有文件。
- 正在播放的曲目被移动后，刷新后的播放器路径应指向新文件；被删除时停止播放并清空当前曲目。
- 部分失败时显示“成功 X 首，失败 Y 首”，并列出最多若干条具体原因；完整错误保留在应用日志中。
- 关闭弹窗不启动操作；操作提交后不能通过重复点击再次执行。

## 测试与验收

- 组件测试覆盖单选、Shift 连选、当前结果全选、半选、虚拟滚动后保持选择，以及切换文件夹或筛选时清空选择。
- IPC 测试覆盖请求字段、ID 去重、数量限制、删除模式、目标游戏和播放列表验证。
- 数据库测试覆盖批量收藏、取消收藏、播放列表去重、移动后关系保留和批量删除级联。
- 文件服务测试覆盖正常移动、同名避让、数据库失败回滚、删除暂存回滚和路径越界拒绝。
- 集成测试覆盖每个批量工具栏操作、成功后计数刷新、部分失败保留选择，以及正在播放曲目的移动和删除。
- 完整测试、TypeScript 静态检查和 Electron 正式构建必须全部通过。

## 验收结果

当用户进入任一已有游戏音乐文件夹时，可以对当前筛选结果中的任意多首歌曲进行可靠批量操作。所有操作只需一次确认和一次批量请求；移动不会覆盖文件，删除明确区分保留与删除硬盘文件，失败不会静默产生不可追踪的数据库与文件状态分离。
