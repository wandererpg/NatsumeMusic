# GalMusic SM2MPX 游戏音频导入设计

## 目标

让用户可以直接选择《家族計画 ～追憶～》这类使用 Studio Miris `SM2MPX10` 无扩展名容器的游戏目录，GalMusic 自动提取其中的音乐并按现有音频导入流程入库。

## 已确认的格式

该游戏目录中的资源不是普通音频文件，而是无扩展名的 `SM2MPX10` 容器：

- `WMSC`：音乐容器，实测可由 `GARbro.Probe.exe` 解出 27 个 `.ogg`。
- `VOICE1`、`VOICE2`：角色语音容器，只有用户打开“导入语音”时才参与导入。
- `SE`、`GGD`、`GGD2`、`ISF`、`DATA` 等：音效、脚本或其他游戏资源，不作为音乐容器导入。

## 现有链路与本次改动

现有主进程已经具备正确的核心链路：通过 `SM2MPX10` 文件头和容器名识别 `WMSC/VOICE*`，深度扫描时将其交给 `GARbro.Probe.exe`，解出的 OGG 再进入普通扫描、时长分类、复制和 SQLite 入库流程。本次不重复实现另一套解码器，也不要求用户重命名或手动解包。

本次改动聚焦于可发现性和回归保障：

- 扫描对话框明确说明深度扫描支持无扩展名 `SM2MPX/WMSC` 音乐容器。
- 在导入选项中说明默认只导入音乐；`VOICE1/VOICE2` 由现有“导入语音”开关控制。
- 通过测试锁定真实容器头格式、音乐/语音筛选和 Probe 选择行为。
- 通过一次真实资源验证确认该目录的 `WMSC` 能解出 OGG，生产包仍携带所需 GARbro Probe 资源。

## 用户流程

1. 打开“导入游戏音乐”。
2. 选择整个游戏目录，例如 `D:\BaiduNetdiskDownload\h\家族計画 ～追憶～`，不要选择单个 `WMSC` 文件。
3. 保持“深度扫描归档”开启；该选项默认开启。
4. 保持“导入语音”关闭即可只导入音乐；需要语音时再开启。
5. 点击“开始导入”。应用会在临时目录解包，复制 OGG 到用户音乐库，并在完成后清理临时目录。

原始游戏目录和容器文件不会被修改。

## 错误处理

- 普通文件扫描和无扩展名容器扫描互不干扰；`WMSC` 不会作为普通音频文件直接复制。
- 无法识别或解包失败的容器进入现有扫描错误结果，不阻止其他可用音乐入库。
- 用户关闭深度扫描时，不扫描任何归档容器，行为与现有导入约定一致。
- 用户关闭“导入语音”时，不打开 `VOICE1/VOICE2`，避免无意导入大量语音。
- 解包失败时原始容器保持不变，并清理应用创建的临时目录。

## 测试与验收

- 格式测试使用 `SM2MPX10` 头和 `WMSC/VOICE1/VOICE2/SE` 容器名，确认分类结果分别为 music、voice、other。
- 导入测试确认深度扫描会把 WMSC 交给 Probe，并在关闭语音时跳过 VOICE 容器。
- 扫描对话框测试确认用户可看到 `SM2MPX/WMSC` 支持说明，默认深度扫描开启，语音仍默认关闭。
- 运行完整测试、TypeScript 检查、资源校验和 Windows 生产构建。
- 使用实际目录中的 `WMSC` 执行一次 Probe 解包验证，确认退出码为 0 且产生 `.ogg` 文件。
- 验证打包后的 `resources` 仍包含 `GARbro.Probe.exe` 和 `Formats.dat`。

## 非目标

- 不导入 `SE`、`GGD` 等非音乐资源。
- 不修改游戏资源文件，不向原目录写入解包结果。
- 不把语音默认混入音乐库。
- 不新增外部解码器或要求用户安装额外程序；继续使用随应用提供且已通过资源校验的 GARbro Probe。
