# VNDB / Bangumi 作品选择与确认设计

日期：2026-10-14。状态：已实现并通过开发版验证。

## 目标和当前缺口

让用户能看到匹配候选、选择正确作品、确认保存，并在以后更换匹配或更新资料。日常通过现有 Electron + Vite 开发验证；已完成候选选择、保存确认及导入结果入口；不增加版本号、不生成 EXE。

设计开始时核对的缺口（现已修复）：

- `src/main/services/game-metadata.ts` 将 `matched` 与 `candidates` 写入 `game_sources.data_json`，但 `toSummary()` 只传递匹配摘要。
- `src/shared/types.ts` 的 `GameMetadataSourceSummary` 没有候选列表和用户确认信息。
- `GameEditor.tsx` 只显示“待确认”，提示“请刷新或手动确认封面”，没有选择作品的操作。
- IPC / preload 只有读取、刷新接口，没有搜索指定名称、按 ID 查询和保存用户选择的接口。
- 强制刷新会重新按本地作品名称搜索，缺少保留手动绑定的规则。
- Bangumi 虽请求最多十个结果，但当前 `searchBangumi()` 只返回前三个补充详情后的候选，其余结果被丢弃。

因此需要补全候选展示、选择草稿、保存绑定的整个流程，单独添加一个按钮不能完成确认。

## 推荐交互

在现有“编辑游戏文件夹 → 网络资料”中，每个来源各显示一张状态卡：

| 状态 | 显示内容 | 操作 |
| --- | --- | --- |
| 待确认 | 候选数量、搜索词 | 选择作品 |
| 已自动匹配 | 当前条目标题、来源 ID、资料摘要 | 更换匹配、更新已关联资料 |
| 已手动确认 | 当前条目摘要、确认标记 | 更换匹配、更新已关联资料 |
| 无结果 | 没找到游戏条目 | 修改搜索词、输入链接或 ID |
| 查询失败 | 失败原因 | 重试、输入链接或 ID |
| 未查询 | 尚未获取资料 | 搜索作品 |

有候选时按钮始终可点击；已经匹配的作品也可以更正。导入结束页的“待确认”旁增加“选择作品”，点击后打开该作品编辑器并定位对应来源。用户可以稍后处理，不阻断歌曲导入。

两个来源独立选择，可以只确认一个来源。每个来源最多关联一个外部 ID；选择不同来源不会合并成本地新游戏，也不会影响曲目归属。

### 候选面板

点击“选择作品”后，在同一编辑对话框内切换到来源候选面板，保留作品名称和封面编辑草稿；避免叠加两个模态框。

```text
← 返回编辑                 选择作品 · VNDB

搜索词 [当前作品名称                  ] [搜索]
或输入 [作品链接 / v12345             ] [获取]

候选列表                         选中作品预览
○ 封面 · 中文名 / 原名            封面、标题、别名
  开发商 · 发售日期 · v12345       开发商、日期、简介
○ 封面 · 本篇 / 重制版             来源 ID · 查看原始条目
○ 封面 · 同名其他作品             评分（注明来源）

                 [取消选择] [使用此作品]
```

- 先展示缓存候选，重新联网搜索由用户触发。
- 第一项可以标为“推荐”，但多候选场景不默认替用户确认。
- 点击候选卡或使用键盘选中后，右侧预览对应作品；没有选择时“使用此作品”禁用。
- 标题、封面、来源 ID 是核心信息；开发商、日期、别名在上游有数据时展示，缺失时不编造。发行日期需要扩展当前归一化字段。
- 评分标明来源，采用各来源正确量纲，不将评分当作匹配置信度。
- 列表显示本次返回的全部有效候选，初次最多十项；首期不承诺全站分页。
- 选中条目时按需获取详情；失败仍能预览已有摘要，提供重试，不能伪装成完整详情。
- 图片失败显示占位，仍可选择；简介按纯文本显示，不将来源 HTML 直接注入。
- “查看原始条目”由主进程根据来源和 ID 构造 URL 并打开系统浏览器。

### 选择与保存

“使用此作品”只更新编辑草稿，返回网络资料区，显示“已选择，尚未保存”；只有编辑器底部“保存更改”成功后才显示“已手动确认”。这样现有“取消”具有一致含义。

保存前展示：各来源的所选标题与 ID、封面处理方式。默认保留当前显示名称；网络搜索词和匹配选择都不改变音乐目录。

封面提供一个统一选项：保留当前封面 / 使用 VNDB 封面 / 使用 Bangumi 封面。选择条件为该来源已有有效匹配或草稿选择且存在可用图片。

- 已有手动封面时默认保留，替换必须由用户显式选择。
- 无封面时可建议采用已选择条目的封面，并在保存预览中明确展示。
- 用户本次选了本地图片时以该图片为准，切换到网络封面需明确取消本地图片选择。
- 取消编辑丢弃所选条目、搜索草稿和封面草稿；搜索缓存可以保留，但不能改变已确认的绑定。
- 保存成功刷新编辑器、作品列表及详情区域；重新打开和重启后仍显示同一绑定。
- 封面下载失败不撤销已成功保存的资料绑定，保留原封面，并明确提示“资料已保存，封面下载失败”，提供仅重试封面的操作。

## 更新规则

将现有含义不清的“刷新网络资料”拆分为两类操作：

1. **更新已关联资料**：按已有 external ID 获取最新详情，保留绑定和用户确认标记；失败显示旧缓存及错误，不把已确认身份变成“待确认”。
2. **更换匹配 / 重新搜索**：按用户输入的名称产生候选草稿，选择并保存后才替换旧绑定。

自动导入继续允许高置信度匹配；一旦用户手动确认，自动任务不得根据文件夹名重新绑定。用户修改本地显示名称也不能触发身份替换。两个来源失败和重试互相独立。

## 数据与服务边界

区分三种信息：已保存的绑定、候选搜索缓存、编辑器的未保存草稿。查询成功不等于用户已确认，搜索失败也不应清空旧绑定。

### 数据库

保留现有 `game_sources` 表，按迁移增加：

- `match_method`：`auto` / `manual` / NULL；历史 matched 默认 auto。
- `confirmed_at`：用户确认时间；自动匹配为空。
- `search_status`：最近候选搜索结果，和当前绑定状态分开。
- `search_error`、`search_fetched_at`：最近搜索错误与时间。
- `revision`：绑定与资料写入的修订号，防止并发写入静默覆盖。

继续用 `data_json.matched` 保存当前详情，用 `data_json.candidates` 保存候选缓存；候选搜索只更新 candidates 及搜索字段，不改 matched、external_id、已确认状态。

历史 ambiguous 的候选可直接读出供选择；历史 failed 但仍有匹配详情的记录保留旧缓存并标记错误；非法 JSON 降级为空候选，可重新查询。两来源独立迁移，不清空已有资料。

### 主进程服务与 IPC

具体命名在实现时沿用项目规范，职责固定为：

- `getGameMetadata(gameId)`：返回已保存摘要、确认方式、修订号与经过校验的候选摘要。
- `searchGameMetadata(gameId, source, query)`：候选搜索，可缓存；不会改变已保存绑定或封面。
- `lookupGameMetadata(gameId, source, input)`：解析 ID / 链接并获取条目详情，返回主进程持有的候选标识。
- `refreshGameMetadata(gameId, source?)`：有绑定时按 ID 更新；无绑定时搜索候选。返回每个来源独立结果。
- 扩展现有作品保存请求，携带 `metadataSelections`、`expectedRevisions` 和 `coverSelection`。renderer 只提交来源及主进程候选标识，不能提交任意完整资料对象或图片 URL。

VNDB 允许 `v12345` 和官方条目链接；Bangumi 允许数字 ID 与 `bgm.tv` / `bangumi.tv` / `chii.in` 的 subject 链接。拒绝不属于支持来源的 URL；实际联网请求使用主进程构造的官方 API 地址。

网络任务按 gameId + source 隔离，使用请求编号防止后返回的旧搜索覆盖新结果；关闭编辑器后不继续更新已卸载界面。手动确认与自动导入、刷新串行化，保存时检查绑定修订号；冲突显示“资料已更新，请重新确认”。

### 保存一致性与封面

保存时先校验全部输入与候选归属，再准备需要的文件操作；所有作品字段和两个来源绑定在一个 SQLite 事务中写入。复用现有目录重命名的校验和失败恢复，不因网络标题自动触发重命名。

封面先下载至应用管理的独立 UUID 临时位置，验证类型、大小与目录边界。下载失败仍可保存资料，原封面保持；成功后事务更新封面路径与来源。数据库保存失败清理本次临时资源，保留原绑定与原封面。

只清理可验证为应用自己创建的旧封面；不删除扫描目录中用户自有图片。旧游戏删除后迟到的请求不能重新创建资料记录。候选缓存必须归属相同 gameId 和 source，不能用另一个作品的候选标识保存。

## 实施顺序和验收

1. 扩展候选类型与迁移，完善 Bangumi 候选保留、按 ID 查询与用户绑定规则。
2. 添加候选搜索、详情、保存的服务和 IPC，完成主进程参数验证。
3. 实现候选面板和保存草稿，接通编辑器与导入完成页入口。
4. 接通封面选择、独立重试和保存后界面刷新。
5. 通过针对性测试、类型检查及 Vite 开发流程验证。仅在涉及构建问题时做构建校验；不运行 EXE 打包。

必须覆盖的行为：

- ambiguous 的缓存候选可显示，选择第二个或第三个后保存，重启仍关联同一 external ID。
- 无选择不能确认；选择后未保存不显示“已确认”；返回、取消和关闭不改旧绑定。
- 修改搜索词不改本地作品名；搜索返回与本地名称不同的条目仍可手动确认。
- Bangumi 第四个及后续有效候选仍能展示和选择。
- 名称、ID、合法链接入口都走同一选择和保存路径。
- 单个来源失败，另一个来源可正常选择和保存。
- 已手动确认的作品在更新资料、改名和再次导入后保持身份。
- 旧请求后返回、并发刷新与保存、作品删除后请求完成均不会覆盖新选择。
- 手动封面默认保护；明确更换网络封面后展示新封面；下载失败保留原图并提供重试。
- 错误候选 ID、跨作品候选、非法来源或链接由主进程拒绝。
- 保存后各视图一致刷新，关闭重新打开及重启后状态一致。

完成标准是用户能从“待确认”进入候选选择，经保存后得到持久化的“已手动确认”；本文件记录设计及本轮实现验收结果。
