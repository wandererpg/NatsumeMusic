# NatsumeMusic 应用更新

0.1.1 增加 Windows 安装版的应用内更新。下载后需要点击「重启更新」生效。正式包从公开的 [GitHub Releases](https://github.com/wandererpg/NatsumeMusic/releases) 获取更新，无需登录或配置令牌。

## 现有用户首次接入

1. 关闭正在运行的 NatsumeMusic。
2. 运行 `NatsumeMusic-0.2.1-x64.exe`，选择原来的安装目录。无需卸载旧版。
3. 启动应用，打开「设置 → 关于与更新」，确认当前版本为 0.2.1。
4. 后续有更高版本正式发布时，点击「检查更新 → 下载更新 → 重启更新」。下载期间可以继续播放，普通关闭应用不会自动安装。

启动时会后台检查版本。更新尚未发布或网络不可用时，当前版本仍可继续离线播放。0.1.0 没有更新代码，必须先手动升级一次；本地打包不等于已发布，GitHub 尚无更高版本时无法下载新更新。

## 数据与失败处理

- 更新保持原安装目录和音乐目录；歌单、收藏、外观及音量设置保留。
- 安装准备阶段保存当前歌曲和播放位置，使用 SQLite 备份 API 备份包含 WAL 的音乐库；新版本启动时，在执行数据库迁移前再次备份。
- 备份位于应用数据目录的 `backups` 文件夹，数据库旁的 `app-database-version` 记录已运行版本。
- 新版本恢复歌曲和位置并保持暂停，由用户选择继续播放。
- 导入、扫描或其他文件操作尚未结束时，需要先等待任务完成再安装。准备备份期间不能开始新的写入任务或关闭窗口。
- 备份失败时取消安装并恢复使用；安装器启动失败时可继续使用应用，请正常关闭并重新打开后再尝试更新。
- 便携版在更新面板中提供手动下载入口。关闭应用后，将新便携包解压到新文件夹并运行，保留完整目录结构。

## 维护者发布流程

1. 修改版本号，更新发布说明。不得将相同版本号的重新打包当作新更新。
2. 运行 `npx tsc --noEmit`、`npm test`、`npm run verify:resources`。
3. 关闭占用原生模块的开发进程，运行 `npm run rebuild:native`、`npm run build`，然后执行 `npx electron-builder --win --publish never`。每一步失败时停止。
4. 检查包内版本、主进程/preload 代码、SQLite 原生模块与 GitHub 更新源；核对 `latest.yml` 中 EXE 的文件名、大小、SHA-512。
   使用 `node scripts/verify-release.mjs release-v0.2.1` 可核验当前版本的发布目录，并生成便携 ZIP、校验文件及 `verification.json`；已存在同名便携 ZIP 时脚本会停止，避免保留旧文件。新版本请替换目录中的版本号。
5. 将 `win-unpacked` 的完整内容打成便携 ZIP，生成 `SHA256SUMS.txt`。保留 EXE、对应 blockmap 与 `latest.yml`。
6. 获得发布授权后，在 `wandererpg/NatsumeMusic` 创建对应版本的正式 Release，上传 EXE、blockmap、latest.yml、便携 ZIP 与 SHA256SUMS。草稿和预发布不会被正式客户端当作稳定更新。
7. 发布后从上一正式安装版本检查、下载并重启更新，核对数据和播放记录。失败时保留日志与备份，并停止继续推广该版本。

更新检查使用固定 GitHub 源。不要在正式客户端加入任意更新 URL、命令执行或令牌配置入口。

## 本次验证

隔离测试脚本：`node scripts/verify-auto-update.mjs`。它生成具有独立应用标识、产品名、可执行文件名、安装目录、用户数据和更新缓存的 QA 包，通过仅监听 `127.0.0.1` 的临时服务完成真实 NSIS 升级。NSIS 从产品名生成其进程检测与启动名称，因此产品名和可执行文件名必须一起隔离。测试不会发布版本或升级真实安装。

0.1.1 → 0.1.2 QA 升级验证安装位置保持不变，音乐目录、音量、歌曲和歌单保留，恢复至 42 秒并暂停，SQLite 完整性为 `ok`，安装前与迁移前备份均存在。正式交付版本为 0.1.2，发布状态以 GitHub Releases 为准。

本轮使用独立产品名的隔离测试完成安装后未自动拉起；手动启动新版后通过上述数据校验。本轮未验证自动重新打开成功。如果重启更新后窗口没有重新出现，可以从原快捷方式启动应用。

最终代码通过 TypeScript 检查、54 个测试文件中的 307 项测试，以及资源完整性检查。审查发现的异步安装失败退出与重试问题已修复并增加回归测试。

`node scripts/verify-library-directory.mjs` 会隔离打包并验证选择已有歌曲目录、音频播放、重启后收藏与歌单保留以及原文件不移动。
